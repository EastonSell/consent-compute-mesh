# Frozen protocol: bounded resident contiguous placement

Frozen before implementation or scenario-result calculation on 2026-10-22. This is a prospective, pure analytical extension of the paper pinned at EastonSell/household-compute@0a58ffda9f982509ba76dd5f333dc8dfad90cf42. No network, device, model, installation, or supervisor experiment was performed.

## Question and evidence boundary

Does an explicit resident, single-stream, contiguous-layer chain fit a supplied inventory after charging local state, and what directed communication lies on that chain? A positive result is a certificate of this arithmetic model under supplied assumptions, not proof of runtime/operator support, measured safe memory, numerical quality, consent enforcement, security, sustained service, or a representative household. A negative result rejects only this model/inventory; offload, tensor parallelism, weight streaming, recomputation, revisiting a device, other graphs and different models are out of scope. No originality or prior-system performance superiority is claimed.

Inputs are scenario assumptions unless individually identified as documentary constants. Missing measured allocations, eligibility, layer tensors, workspaces, compute times, link distributions, energy, thermal limits and consent remain unknown. We do not replace them with vendor RAM, nominal FLOPS, averages, zeros, or a synthetic national inventory.

## Model version 1

- Memory units are exact nonnegative integer bytes; GiB is 2^30 bytes. Time/rates are exact rational arithmetic; Mbps is 10^6 bits/s. No floating-point comparison decides fit.
- There are 1..128 ordered transformer blocks, each with resident weight bytes, KV bytes and peak workspace bytes. KV means keys plus values for a frozen context/concurrency/format; it is not an allocator peak.
- A used device owns one nonempty contiguous block interval. Each device may occur once. Unused devices consume no model-accounted reserve. All layers are covered exactly once in order.
- Devices have one simultaneously addressable allocation, a fixed runtime reserve, tri-state eligibility, tri-state support for each layer and for embedding/head operations. Installed/unified/host/accelerator memory is not added automatically. Budgets exclude ordinary duties; that exclusion is a supplied contract, not a measurement here.
- The first stage hosts embeddings and a fixed controller reserve. The last hosts the output head. For untied endpoints both resident byte quantities are charged. For tied embeddings/head their byte quantities must agree: one copy is charged when first and last are the same stage; otherwise a copy resides on each endpoint stage. Intermediate stages do not carry endpoint copies. The model does not treat weight tying as remote zero-copy access.
- Stage memory = local layer weights + local layer KV + endpoint weights + runtime reserve + global per-stage activation reserve + maximum workspace among its layers and any endpoint operations + controller reserve on the first stage. Workspaces are max, not sum, under the expressly sequential implementation. Activation reserve is separate from link payload; it includes whatever simultaneous buffers the supplied implementation requires. No implicit 20% or 2 GiB safety factor is added.
- A direct directed link has tri-state availability, optional nonnegative latency_ns, and optional positive payload_bps. Missing links are unavailable, not unknown. Unspecified metrics are unknown, not zero. No relay path is silently synthesized.
- Each stage boundary sends the fixed activation payload. If there is more than one stage, a fixed feedback payload returns directly from final to first stage before the next dependent token. Transfer time is latency_ns + bytes*8*10^9/payload_bps. All listed transfers are serial on the one-token critical path. Known layer and endpoint compute_ns are summed once; any unknown term leaves total compute/critical path unknown. No queueing, protocol, encryption, packet, contention, initialization, prefill, recovery or tail allowance is inferred.
- A deadline is evaluated only against the resulting modeled path. Passing a complete supplied path is not measured latency. When compute is unknown, communication is a lower bound and cannot certify passing a deadline.

## Unknowns, certificates and search

The solver first searches only placements whose eligibility, support, budgets and directed connectivity are known. Unknown link metrics or compute do not prevent a memory/connectivity certificate, but remain explicit in timing. If no such placement exists, an optimistic relaxation allows unknown eligibility/support/connectivity and an unlimited unknown budget solely to distinguish `unknown` from a proven contradiction. The relaxed witness is not a certified placement. It never becomes a measurement or a zero-cost claim. Explicit false values and absent links remain false in the relaxation.

Statuses: `feasible` means known memory/connectivity placement; `unknown` means a relaxed witness exists but no known placement; `infeasible` means even the relaxation has no placement; `search_incomplete` means a resource cap prevented the decision. Exhaustion is never reported as infeasibility. The solver minimizes stage count, then deterministically chooses by input device order and split order; it does not claim to optimize latency. Its certificate records intervals, per-stage accounting, directed transfers and exact timing/unknown terms, bound to a canonical scenario SHA256. A separate checker must recalculate these without importing solver/accounting helpers. The checker verifies a witness, not minimality or general solver correctness.

Negative evidence: necessary bounds use maximum eligible allocations and maximum individually fitting contiguous-layer counts, deliberately ignoring endpoint/controller penalties when doing so is optimistic. If their sum is below total demand, that is a checkable no-placement argument. A stricter first-stage count bound will account for controller/embedding costs where all possible first devices can be enumerated. General exhausted-search negatives are labeled finite-search results, not independent proof certificates.

## Prospective cases and grids (fixed before results)

1. Hand-checkable failures: four indivisible 3 GiB blocks into 8/2/2 GiB; contiguous [2,6,2] GiB into 4/6 GiB (noncontiguous grouping would fit); per-stage-reserve failure; endpoint/tied-duplication failure; ineligible and unknown devices; unknown links/compute; asymmetric link/feedback checks; a deliberately capped search.
2. Envelope-matched arithmetic surrogate, **not an actual 70B architecture placement**: 80 equal layer blocks, total layer weight-plus-format bytes = 1.20*(70*10^9*4/8) = 42*10^9, KV = 80*(2*8*128*8192*1*2) bytes, controller reserve 2 GiB, no endpoint weights in the zero-endpoint row. This reproduces the paper's unique aggregate envelope but intentionally exposes the missing tensor decomposition. Each selected home has exactly allocations [8,2,2] GiB, all eligibility/support true by assumption. Home count grid 3..6; per-stage activation/runtime-extra reserve grid [0,64,128,192,256,384,512] MiB. No compute time is supplied.
3. Tied endpoint sensitivity: home counts 4 and 5; tied endpoint bytes [0,0.5,1,2,3,4,8] GiB; remove exactly one endpoint copy from the 42*10^9 total layer weights, distributing the remainder equally across 80 layers (the chosen grid is divisible in bytes). Thus the unique aggregate remains fixed; splitting endpoints exposes duplication. Workspace grid [0,64,256] MiB per used stage, activation reserve zero.
4. Link scenarios: direct intrahome 1000 Mbps/1 ms and interhome 20 Mbps/20 ms, activation 16,384 bytes, token feedback 4 bytes. These reproduce paper assumptions, not observations. Report actual certificate boundaries, separately from hypothetical one-stage-per-home calculations. Compute remains unknown. Also report all-20-Mbps links and missing/unknown return-link cases.
5. Baselines: aggregate-memory necessary condition; best single eligible device; fixed input-order maximal-prefix greedy; descending-budget maximal-prefix greedy; exact bounded solver. Baseline failure does not prove no placement. Report count, stage count, bytes and communication lower bound only when valid. No best-device offload/independent-request benchmark is claimed for an oversized resident model.
6. Exhaustive tiny oracle: enumerate every case with 1..3 devices, 1..4 layers, layer resident weights in {1,2}, capacities in {1,2,3}, zero extra terms and complete known links. Enumerate all device permutations and all cut compositions separately from solver search. Add finite selected endpoint, reserve, eligibility and link asymmetry fixtures, tampered certificates and deterministic reruns. This finite oracle establishes agreement only on the enumerated domain, not a universal proof.

## Resource and integrity caps

Python standard library only; no model weights or package installation. Maximum scenario size 12 devices / 128 layers; built-in search cap 250,000 visited states and 5,000,000 candidate transitions per pass; stop and report incomplete if reached. At most 150 substantive scenario rows plus the predeclared tiny enumeration (at most 20,000 cases). Individual test/reproduction processes get a 120-second shell timeout; suite logs preserve timeout/failure rather than relabeling success. Deterministic output artifacts exclude wall-clock timings.
